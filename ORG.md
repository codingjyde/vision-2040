# ORG.md

Owner: Rhema Nigeria

Purpose: Define the documentation framework used to organise Rhema Nigeria's institutional knowledge.

Status: Initial scaffold

## Organisation

Rhema Nigeria is the organisation represented by this repository.

Vision 2040 is the current long-term programme context for organising and developing this knowledge base.

## Org Kit Artefacts

The repository is organised around the following artefact types.

| Artefact | Purpose |
| --- | --- |
| Mission | Defines why the organisation exists. |
| Vision | Defines the future the organisation is moving towards. |
| Principles | Define enduring beliefs, rules, and decision filters. |
| Operating Model | Explains how the organisation works as a system. |
| Capabilities | Define what the organisation must be able to do. |
| Governance | Defines authority, accountability, oversight, and decision rights. |
| Policies | State approved rules and required standards. |
| Procedures | Provide step-by-step instructions for repeatable work. |
| Playbooks | Provide practical guidance for recurring scenarios. |
| Guides | Explain concepts, practices, roles, or development pathways. |
| Templates | Provide reusable blank structures. |
| Checklists | Support execution, review, and quality control. |
| Knowledge Base | Preserves institutional learning and explanatory material. |
| References | Preserves source material, research, history, and external inputs. |

## Authority Hierarchy

Documents should reference higher-authority artefacts instead of copying their content.

1. Mission and vision
2. Principles
3. Programme charter
4. Operating model and capabilities
5. Governance
6. Policies
7. Procedures, playbooks, and guides
8. Templates and checklists
9. Knowledge base, references, and sources

## Programme And Capability Separation

Vision 2040 workstreams are temporary delivery structures.

Capabilities are enduring organisational abilities that should remain useful after the workstreams close.

Workstream folders should preserve execution history, drafts, validation evidence, reports, risks, and handover material.

Capability folders should hold the durable models, frameworks, and institutional knowledge that Rhema Nigeria will continue to maintain.

When a workstream produces a stable model, the model should move into the relevant capability or artefact folder and the workstream document should reference it.

## Cross-Reference Rules

Documents should link to authoritative sources rather than copy their content.

Use relative Markdown links.

Each significant document should include a related documents section where relevant.

Cross-reference:

- source material
- parent capability
- related decisions
- related policies
- related procedures
- templates used
- superseded documents
- affected documents

## Naming Conventions

Use lowercase kebab-case for Markdown filenames.

Use dated filenames for meeting papers and reports.

Use numbered IDs for decision records.

Examples:

- `campus-launch-playbook.md`
- `decision-rights-model.md`
- `2026-03-15-pmo-meeting-paper.md`
- `ADR-0001-documentation-architecture.md`

Avoid filenames such as `final-final.md`, `new-plan.md`, or `updated-policy.md`.

## Maintenance Rules

Every document should have a clear owner and purpose.

Principles should be separated from procedures.

Facts should be separated from opinions, proposals, and assumptions.

Templates should be separated from completed instances.

References should preserve source material without becoming policy.

Decisions should record rationale, not just outcomes.

## Document Metadata

Each significant document should begin with:

- Owner
- Purpose
- Status
- Version, where applicable
- Last updated, where applicable
- Related documents, where applicable
